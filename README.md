# Web Serial VT100 Terminal

Web Serial API と [Xterm.js](https://xtermjs.org/) をベースとし、 **「ターミナル（ブラウザ）側にコマンド履歴およびデバッグログ保存機能を持たせる」** ことで、組み込み機器側のCLI・デバッグロジックを極限までシンプルに保てるよう設計されています。

## 主な機能

- **単一ファイル構成**: ビルドツールやサーバーは不要です。`web-serial-vt100-terminal.html` をブラウザ（ChromeやEdgeなど）で開くだけで使用できます。
  - ※ Xterm.js は CDN (jsDelivr) から読み込むため、**初回はインターネット接続が必要**です。完全オフラインで使う場合は、Xterm.js のファイルをローカルに置き、HTML 内の `<link>` / `<script>` の URL を書き換えてください。
- **高度なローカル行編集**:
  - ブラウザ側でコマンドをバッファリングし、左右のカーソル移動 (`←`/`→`)、バックスペース、Deleteキーによる編集が可能。
  - マイコン側のプロンプト（`>` や `uart:~$` など）を消去してしまわない安全な部分再描画方式を採用。
  - Enter で入力行をまとめて送信します（改行は **LF のみ**。CR は送信しません）。
- **充実した履歴機能**:
  - 矢印キー (`↑`/`↓`) によるコマンド履歴の呼び出し（LocalStorageに最大100件保存）。
  - 直近20件（重複除く）の履歴をすばやく選択・送信できるクイック送信ドロップダウン。
- **受信データの自動整形**:
  - 受信した CR (`\r`) はすべて破棄し、LF (`\n`) のみを行区切りとして扱います。
  - 自分が送信したコマンドのエコーバックを自動で除去します（1文字ずつ返ってくる場合も対応）。
  - 空行を表示・記録しません（画面とログの両方）。デバイスが意図的に送る空行も除去されます。
- **タイムスタンプ付与**:
  - 各行の行頭にミリ秒精度の時刻 `[YYYY-MM-DD hh:mm:ss.mmm]` を付与（「タイムスタンプ付与」チェックボックスで ON/OFF）。
  - 一括で届いた複数行も、同一時刻にならないよう順序を保って補正します。
  - コマンド行は、プロンプトが表示された時刻ではなく **Enter を押した（送信した）時刻** に更新されます（画面・ログの両方）。
- **ログ保存 & ユーティリティ**:
  - 受信ログに加えて、**入力・送信したコマンドも記録**し、`serial_YYYYMMDD_hhmmss.log` として一括保存。
  - ログ保存時、エスケープシーケンスは除去されます。
  - ログバッファとターミナル画面（スクロールバック 30000 行）を一括クリア。
  - ターミナル領域は縦方向にドラッグしてリサイズでき、ウィンドウサイズにも自動追従します。
- **自動フォーカス管理**: 接続や各種ボタン操作の完了と同時にターミナルへ自動フォーカスし、すぐにキーボード入力が可能。

## キー操作

| キー | 動作 |
| --- | --- |
| `↑` / `↓` | コマンド履歴の前 / 次を呼び出す |
| `←` / `→` | カーソル移動 |
| `Backspace` / `Delete` | カーソルの左 / 位置の文字を削除 |
| `Enter` | 入力行を送信（LF のみ） |
| `Ctrl+C` (`Cmd+C`) | テキスト選択中: クリップボードへコピー<br>未選択時: 入力中の内容を破棄し、割り込み `0x03` を送信 |
| ドラッグ選択 | ターミナル内のテキストを選択 |

## ログの例

```
[2026-10-25 18:22:06.563] ECLI> help
[2026-10-25 18:22:06.564] Available Commands:
[2026-10-25 18:22:06.566]   help        : Show available commands
[2026-10-25 18:22:06.568]   version     : Show firmware version
[2026-10-25 18:22:16.793] ECLI> version
[2026-10-25 18:22:16.795] ECLI Firmware v1.0.1
[2026-10-25 18:22:16.796] ECLI> 
```

`ECLI> help` の行の時刻は、プロンプトの表示時刻ではなく、コマンドを送信した時刻です。

## 接続するデバイス側の前提

- シリアル設定: **8N1 固定**（データ8bit / ストップ1bit / パリティなし）。ボーレートは 9600〜921600 bps から選択（デフォルト `115200 bps`）。
- 行区切りは **LF** で受信できること（受信データの CR は破棄されます）。
- コマンドのエコーバックは、**あってもなくても動作します**（あれば自動で除去されます）。

## 使い方

1. このリポジトリをクローンまたはダウンロードします。
2. Web Serial API対応ブラウザ（Google Chrome、Microsoft Edgeなど）で `web-serial-vt100-terminal.html` を開きます（※ブラウザの仕様上、`file://` では制限される場合があるため、ローカルサーバー (`http://localhost` など) 経由での実行を推奨します）。
3. ボーレート（デフォルト: `115200 bps`）を選択し、**「接続」** ボタンをクリックします。
4. 接続するシリアルデバイス（マイコンボードなど）を選択します。
5. ターミナルにコマンドを入力して `Enter` で送信します。ログは **「ログ保存」** でファイルに保存できます。

> Web Serial API は、Firefox や Safari など一部のブラウザでは利用できません。

## 注意事項・既知の制限

- 受信ログは **メモリ上にのみ保持**されます。ページを閉じる・再読み込みすると消えるため、必要なログは先に「ログ保存」してください（コマンド履歴は LocalStorage に残ります）。
- ドロップダウンからの **クイック送信**では、コマンドは画面には表示されず、ログにのみ記録されます。
- プロンプトを受信しないまま入力した行には、画面上のタイムスタンプは付きません（ログにのみ付与されます）。
- 大量のデータを受信している最中に `Enter` を押すと、画面上の時刻の書き換え位置がずれる場合があります（ログは影響を受けません）。
- シリアル設定は 8N1 固定です（変更するには HTML 内の `serialPort.open()` を編集してください）。

## 開発・改変する方へ

ソースコードは `web-serial-vt100-terminal.html` 1ファイルで、JavaScript は `<script>` 内にまとまっています。誰でも修正しやすいよう、コメントは **Doxygen 形式**で統一しています。

### コメント規約

- 関数・イベントハンドラ・グローバル変数は、`/**` で始まるブロックコメントに `@brief` / `@details` / `@param` / `@return` / `@note` / `@warning` などを使って記述します。
- 変数の説明は、宣言行の末尾に `///<` で記述します。
- 関連する宣言は `@defgroup` でグループ化し、末尾に `end of grp_xxx` の目印コメントを付けます。
- 関数内部の補足説明は、通常の `//` コメントで記述します。

### コードの構成（グループ）

| グループ | 内容 |
| --- | --- |
| `grp_config` | 定数・状態管理変数 |
| `grp_term` | Xterm.js の初期化・サイズ追従・共通ヘルパー |
| `grp_conn` | シリアルの接続・切断 |
| `grp_buttons` | ログ保存/消去、履歴消去、クイック送信ボタン |
| `grp_rx` | 受信データ処理（CR破棄・エコー除去・空行抑止）、タイムスタンプ、ログ記録 |
| `grp_serial_io` | 受信ループ・送信処理 |
| `grp_history` | コマンド履歴の保存とクイック送信プルダウンの更新 |
| `grp_input` | キーボード入力（行編集・Enter送信・Ctrl+C） |

### 実装上の注意

- 画面（Xterm）とログ（`rawLogBuffer`）は、**別々に行の状態を管理**しています（画面: `screenAtLineStart` / ログ: `window._termIsNewLine`）。
- `restampPromptLine()` と `logUserCommand()` は、**画面の改行 (`\r\n`) を出力する前**に呼び出す必要があります。
- Doxygen は `.html` を直接解析しません。ドキュメントを生成する場合は、`<script>` の中身を `.js` として切り出すか、入力フィルタを使用してください。
